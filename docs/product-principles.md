# Product Principles

## 1. Start with a question

Each project should begin with a clear question, observation, or phenomenon.

Good:

- How does Adelaide's petrol price cycle move across the city?
- When does solar generation take over South Australia's electricity supply?
- How has Adelaide's urban footprint changed over time?

Weak:

- Fuel dashboard
- Census chart
- Transport map

## 2. Treat data as material

Do not automatically convert every dataset into standard charts.

Consider how values can control:

- position
- size
- movement
- timing
- opacity
- line thickness
- direction
- shape
- density
- animation speed
- geographic extent

Use conventional charts when they communicate the answer best.

## 3. Visual first

Project pages should reveal the main visual quickly.

Long methodology sections belong lower on the page.

## 4. The site shell stays quiet

Navigation, typography, cards, and page chrome should remain restrained.

Individual projects may use stronger visual identities.

## 5. Mobile is a real target

A project is not complete if it only works on a large desktop monitor.

Touch, narrow widths, reduced labels, and smaller datasets may require a separate presentation strategy.

## 6. Interaction must add meaning

Do not add motion or interaction only because it looks impressive.

Useful interaction includes:

- exploring time
- comparing values
- revealing local detail
- changing scale
- filtering a meaningful dimension
- moving through a narrative sequence

## 7. Explain without writing an essay

Each project should answer:

- What is this?
- What should I notice?
- Where did the data come from?
- What did you do to the data?
- When was it last updated?

## 8. Show the method

Portfolio value comes from demonstrating thinking as well as the final visual.

Include concise methodology and source information.

## 9. Preserve trust

Never imply precision the data does not support.

Label estimates, assumptions, missing data, smoothing, derived fields, and incomplete coverage.

## 10. Publish small things

LAB should make it normal to publish a useful one-evening experiment.

The portfolio should grow through repeated small work, not only rare large projects.
